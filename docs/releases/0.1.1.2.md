# v0.1.1.2 — Verified Linux runtime downloads

This patch fixes Linux runtime provisioning when a packaged OpenSSL library's
compiled certificate paths do not exist on the host distribution. RPG Maker MV
conversion can now download and verify its required NW.js runtime on these hosts.

Linux runtime downloads prefer usable operating-system trust roots. Explicit
`SSL_CERT_FILE` and `SSL_CERT_DIR` configurations are checked and preserved; an
invalid override produces an actionable error. A maintained Mozilla CA bundle is
included as a fallback when system roots are unavailable. Certificate-chain and
hostname verification remain enabled. Windows retains its native Python trust
selection.

Download errors distinguish certificate validation, invalid local CA settings,
HTTP status, DNS failure, timeout, missing official checksum data and integrity
failure. Interrupted NW.js transfers are discarded, incomplete runtime resources
are rejected, and failed cache replacement restores the previous entry. Official
checksums, full SHA256 verification and ARM64 runtime architecture checks remain
mandatory. A valid cache or user runtime override still supports offline conversion.

For a reproducible report, run the converter with `--tls-diagnostics`; add
`--smoke` to request only the official NW.js checksum metadata. See
[TLS troubleshooting](../runtime-tls-troubleshooting.md).

The release retains 0.1.1.1's controller profiles, launch-session fixes, artwork
controls, standalone ARM64 artwork companion, runtime bundles and conversion
provenance. Converter downloads are available for Linux x86_64, Linux AArch64 and
Windows x64. Converted native game packages continue to target Linux ARM64.

## Validation and limits

The fix passed native Linux x64/AArch64 frozen GUI startup, real NW.js checksum
and archive verification, synthetic MV conversion and a repeated conversion from
cache. Windows regression tests and frozen GUI startup also passed. The release
pipeline rebuilds from the exact clean `v0.1.1.2` tag and checks archive identity,
architecture and checksums before publication.

These are automated conversion checks, not Steam Frame gameplay validation.
Game-specific media/plugins remain subject to testing. ZIP inspection still
precedes runtime provisioning for layouts requiring extraction; earlier bounded
archive preflight is a separate follow-up. Non-Steam installation remains the
recommended workflow; original-entry linking and deduplication remain experimental.
