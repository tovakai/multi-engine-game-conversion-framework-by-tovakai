# 0.1.1.2 candidate: Linux runtime TLS reliability

Prepared for review; no tag, release publication, or merge is implied.
The requested base is `integration/working-main` at `4bf0840` (which still
declared 0.1.0), not the newer source used for the published 0.1.1.1 binaries.
This candidate number follows that published release; review branch divergence
before promotion. This patch does not bring unrelated released features into
the older integration branch.

- Linux runtime downloads select readable OS trust roots when packaged OpenSSL
  points to another distribution's certificate paths. A maintained certifi
  Mozilla bundle is included as a last resort when system roots are unavailable.
- Explicit `SSL_CERT_FILE` and `SSL_CERT_DIR` configurations are validated and
  never silently replaced by fallback roots. Windows keeps Python's defaults.
- TLS validation, HTTP status, DNS failure, timeout and local CA configuration
  errors have distinct messages. `--tls-diagnostics` works without a desktop;
  `--smoke` additionally requests only official NW.js checksum metadata.
- NW.js partial transfers are cleaned up, incomplete runtime resources are
  rejected, and cache replacement restores the previous entry on install failure.
- Both native Linux converter build targets share certificate packaging and CI
  checks. Converted game runtimes remain Linux ARM64.

See [TLS troubleshooting](../runtime-tls-troubleshooting.md) and the
[investigation and verification report](../reviews/linux-runtime-tls-2026-10-19.md)
for evidence, commands and validation limits. ZIP inspection before extraction
remains a separate follow-up. Native AArch64 execution, live urllib connectivity
and graphical acceptance must be completed in an environment that supports them.
