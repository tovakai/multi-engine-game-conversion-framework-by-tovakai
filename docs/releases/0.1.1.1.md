# v0.1.1.1 — Controller profiles, launch sessions and artwork controls

Converted Ren'Py and RPG Maker games can now bundle an **experimental controller
profile** with D-pad/left-stick navigation and an R3 toggle for right-stick mouse
control. Pointer mode uses RT for left click/held drag and LT for right click;
pressing R3 again restores native right-stick and trigger output. Enable the
controller-profile checkbox in the converter or use `build --controller-profile`.
Existing converted outputs can use the `controller-profile BUILD` command.

Conversion bundles setup files without changing Steam layouts. On the Frame,
use the included `setup-controller-profile.sh` to list entries and explicitly
apply the profile. The tested Steam client also requires its separate
`--frame-routing --apply` assignment. Both selections have backups and explicit
restore commands; personal templates and newer user selections are preserved.
This works with existing non-Steam entries regardless of how they were added.
See [setup, control bindings and routing limits](../controller-normalization.md).

Games launched through Steam now retain Steam's graphics session while Frametop
is open. Desktop launches retain their caller's desktop session. Shared launchers
no longer import Plasma's display variables, and the optional Steam API graphics
guard preserves the inherited display. Reconvert affected packages to obtain the
updated launchers; existing installed game packages are not patched automatically.

The converter's **Artwork Settings** dialog accepts a masked SteamGridDB API
key and an optional numeric SteamGridDB game ID. A blank ID keeps automatic
matching; a supplied ID chooses the SteamGridDB match for missing artwork.
The key stays in the current session, is passed directly to the artwork worker,
and is excluded from logs and converted-package metadata. Selecting another
source clears the game ID. CLI environment-key support remains available.
Manual/existing artwork and official Steam artwork retain their priority.
A SteamGridDB game ID is not a Steam AppID.

The independent **Steam Artwork Companion** supports local PNG/JPEG files and
optional SteamGridDB fetching for existing non-Steam entries on the Frame.
Select an entry, choose portrait, landscape, hero and logo images, then apply
with Steam closed. Changes have backups and Undo protection. It does not require
our converter or installer. The native ARM64 converter archive includes its
standalone executable in `Steam Artwork Companion/`; copy that whole subfolder
when using it separately. See [use and recovery](../steam-artwork-companion.md).

## Validation and limits

Physical Frame testing confirmed the window probe with the Frame controllers
and an 8BitDo Ultimate 2. Isolated Ren'Py 8.3.7 and RPG Maker MV 1.6.1 games then
passed the requested navigation, action and pointer checks; Ren'Py slider dragging
also passed. In MV, dashboard transitions while holding a direction or mouse
button and 8BitDo disconnect/reconnect left no stuck inputs. MV telemetry showed
ordinary keyboard/mouse events and a final neutral engine state. Original game
entries, layouts and saves remained separate from the test copies.

MZ, mkxp-z, EasyRPG, other controller families and game-specific custom input
scripts remain unverified. Mouse events cannot add clickable interfaces to games
that never implemented them. The Frame routing workaround uses internal Steam
client behavior and remains experimental, with collision guards and restoration.

Companion checks covered local images, mocked SteamGridDB downloads, Apply/Undo,
isolated profiles and standalone ARM64 startup. Authenticated SteamGridDB fetching
and artwork appearance following a real Steam restart were not certified in this
session. No game content, proprietary SDKs or API keys are distributed.

This revision retains the v0.1.1.0 runtime and installation features. Non-Steam
installation remains the recommended workflow; original-entry linking and asset
deduplication retain their existing experimental status. Deferred low-spec
optimization research is documentation only. SMAPI development is outside this
release's scope.
