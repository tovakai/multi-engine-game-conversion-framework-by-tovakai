# 0.1.0 release candidate

Status: preparation on `integration/working-main`. This is not a published
application release. Promotion to `main` and the `v0.1.0` tag are separate steps.

The foundation release provides one Windows x64 / Linux ARM64 GUI and CLI for
inspection, runtime selection, conversion, Frame ZIP packaging and Steam shortcut
installation. Original game installations are preserved. Supported runtime
recipes download automatically, verify checksums and reuse their caches.

## Supported scope and limitations

- RenFrame handles supported Ren'Py 7/8 distributions. Older engines and identified
  nightly exports use explicit compatibility migrations with separate limits.
- RPGMFrame handles RPG Maker MV/MZ through NW.js, XP/VX/VX Ace through mkxp-z,
  and supported Godot exports. Runtime/version and native-module requirements
  remain part of inspection; encrypted or unknown custom exports are not promised.
- GameMakerFrame, LOVEFrame, ConstructFrame, AGSFrame and MonoFrame are included
  as experimental backends. Their presence does not mean every game or native
  plugin works. GameMaker YYC/GMRT is outside the VM runner's scope.
- MonoFrame currently covers the pinned vanilla Steam Stardew Valley 1.6.15
  installation. Through Steam, pointer/gamepad input, early gameplay and save/load
  are user-confirmed. SMAPI implementation is deferred.
- The existing STS2 two-stage workflow is retained as experimental. It requires
  a user-supplied FMOD Linux SDK and device-side finishing. Further STS2 work is
  not a foundation release gate.
- Live2D-dependent Ren'Py games require a separately downloaded, user-supplied
  Cubism SDK. Proprietary SDK libraries and original game assets are not bundled
  with the converter application.

See the [compatibility evidence](../hardware-feedback-2026-10-11.md),
[MonoFrame validation](../monoframe.md), and [native backend limits](../native-backends.md).
Full-game compatibility and Steam online features are separate from successful
conversion or short gameplay tests.

Known reported limitations include Cassette Beasts controller/rendering problems,
Cook, Serve, Delicious! 3 performance/controller problems, Desert Child graphical
glitches, and incomplete controller evidence for The Cat Lady. Do not describe
these as universally fixed by runtime provisioning.

## Install and use

Download the archive for the converter host: `*-0.1.0-windows-x64.zip` or
`*-0.1.0-linux-aarch64.tar.gz`. Extract and run the executable in
`Multi-Engine Game Conversion Framework by tovakai`. The converted game output
is a separate `*-linux-aarch64.zip`.

Transfer the game ZIP to Frame, extract it, and run `./install-to-steam.sh` from
its folder with Steam running. Launch from Steam for controller mapping. Manual
runtime selection is an optional override for supported automatic recipes.

Application archives include `BUILD.json`, `BUILD.txt`, license/third-party
notices and these release notes. The adjacent SHA256SUMS file identifies the
archive checksum. `BUILD.json` records the source commit and whether tracked
source changes were present at build time.

## Remaining release gates

- Passing Windows and Linux tests and frozen Windows/native ARM64 build/startup checks.
- Review artifact provenance, notices and experimental claims for the exact commit.
- Complete the final candidate's representative end-user conversion/install matrix;
  earlier hardware reports are useful evidence, but not a retest of every game.
- Review the promotion PR, merge to `main`, build from that commit, verify both
  archives, then tag/publish `v0.1.0` deliberately.

Runtime prereleases remain independent downloads. A runtime-only tag does not
publish or designate an application release.
