# v0.1.1.0 — Steam Library Integration

Status: development candidate. **Not release-ready: Steam Frame acceptance is
pending.** No public tag or final release has been created. v0.1.0.3 remains
immutable.

An isolated user-requested Until Then profile now integrates the tested native
Godot 4.1.4 recipe into the GUI/CLI converter. It checks the source build hashes,
uses the owner-supplied FMOD 2.02.35 Linux SDK, preserves the original PCK, and
packages all six native extensions with an overlay and shared non-Steam artwork
installer. Research gameplay, audio, controller, save/reload and normal-exit
checks passed; full-game/achievement checks remain unverified. Until Then shared
linking and deduplication remain unsupported. See [setup and remaining production
acceptance](../backends/until-then.md). The Windows development candidate can
include its verified open-source offline runtime; runtime-only public provisioning
is a separate release-preparation gate, not an application release publication.

Fixed the first Stardew hardware-installation blocker: the unified router now
retains verified backend Steam metadata and conversion provenance. A separate
canonical `backend` field lets the installer recognize MonoFrame while preserving
the historical `engine: monogame` value. The same fix covers all five approved
linking backends and the experimental deduplication profile lookup. Affected old
development ZIPs require reconversion; they cannot recover discarded evidence
by rerunning the installer. Steam Frame linking/launch acceptance remains pending.

The extracted ZIP keeps one `install-to-steam.sh`. It offers automatic linking to
the installed original Steam entry for approved native launch contracts, while
retaining live non-Steam registration, duplicate detection and artwork.

**The original Steam game must be installed through Steam on this Steam Frame
before linking is available.** The installer discovers secondary libraries,
checks complete local installations, opens Steam's official installation flow
when needed, and supports rescanning without another transfer.

No original game files are replaced and no running Steam configuration files
are edited by the installer. An existing loopback Steam CEF interface reads
custom options, backs up the exact string, injects the wrapper with
`SetAppLaunchOptions`, and verifies readback. No copying/pasting or Properties
editing is required; unavailable live access offers non-Steam installation.
Recoverable records preserve exact live prior options; repair and automatic restoration are
available on reruns. A matching launch receipt does not prove gameplay, Steam
Input, playtime, achievements or Cloud support.

Optional post-extraction asset deduplication compares backend-selected static
files by size/SHA-256, replaces only identical converted assets with symlinks,
and records recoverable transactions. Experimental Celeste/Stardew XNB
candidates require tested bubblewrap read-only launches; originals are never
modified. Updates/broken links block launching. Standalone asset restoration,
idempotence and measured storage reporting are included. Small durable per-file
journal events replace repeated full-manifest writes. Asset provenance is recorded
after backend preparation to exclude modified/generated resources, while current
Frame assets still require size/SHA-256 validation. Comparison/linking progress
bars and a pre-consent duration warning are included. See
[safety contract and mandatory hardware gates](../steam-asset-deduplication.md).
No backend is advertised as safely deduplicated before real-game acceptance.

Windowed GUI startup now routes dependency warnings to a startup log when console
streams are unavailable. This prevents CustomTkinter's font fallback from
crashing launches from long extraction paths; Windows CI also checks that case.
If Tcl cannot load the optional native drag-and-drop extension, the GUI opens
with its existing folder picker and records the diagnostic instead of failing.

Initial shared capabilities: Celeste's audited vanilla profile, Stardew's audited
MonoFrame profile, and manifest-identified GameMaker, LÖVE and AGS native packages.
RenFrame, RPGMFrame and Godot shared linking are deferred. Hollow Knight retains
Windows ARM64/ARM64 Proton; STS2 retains its specialized two-stage Steam chain.

See [installation, capability matrix and mandatory device checklist](../steam-library-integration.md).
Direct original-file patching, coordinated on-device compilation and broader
maintenance goals are deferred explicitly in the [reconciled plan](0.1.1-plan.md).
ZIP naming and converter provenance retain the existing convention.

Candidate builds use the existing Windows x64 and native Linux AArch64 builders
and CI checks: identities, license notices, checksums and frozen startup receipts.

Release requirement added: provide a **Linux x86_64 GUI converter** for ordinary
Linux PCs, alongside Windows x64 and Linux AArch64. This is a converter host
architecture; converted Frame packages retain their existing ARM64 targets.
The Linux x86_64 artifact still needs packaging/CI support, frozen GUI startup
and conversion validation, build provenance, license notices and checksums.
It is planned work, not an already available or verified release artifact.

Final official artifacts must be rebuilt from the accepted clean tagged commit
after acceptance; candidate artifacts cannot be relabeled as final releases.

Candidate validation after live integration and deduplication improvements:
**602 passed, 18 skipped** in the full Windows regression suite; **141 passed**
in the focused Linux AArch64 fixture suite on Frame. Fixtures never use actual
Steam installations. Real Stardew testing confirmed the converted AArch64 .NET
executable through the original Steam entry, SteamVR view, controller input,
gameplay, saving and relaunch. Live backup, injection, readback, idempotence and
exact restoration passed without restarting Steam or SteamVR. Original file
hashes and metadata were unchanged during the configuration round trip.

Ordinary Steam restart persistence, original-game gameplay after restoration,
other backend hardware acceptance, and the remaining device checklist are still
pending. Playtime and achievements remain unverified. PR #51 stays in draft;
these results do not authorize the public release tag.

Train45 build 25227748 now has an experimental shared GUI/CLI conversion
recipe using Godot 4.5.0 and GodotSteam 4.19.1 ARM64 release binaries. Research
gameplay passed on Frame; production-package acceptance, full-game coverage,
achievements and playtime remain separate checks. Shared Godot original-entry
linking and asset deduplication remain deferred. See [Train45 setup](../backends/train45.md).
